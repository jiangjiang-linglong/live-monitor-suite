# 离线转写与爆品片段切片管线

直播结束后离线跑，**现金成本为 0（用飞书妙记）**，自动完成「录像 → 转写 → 话术关键词定位 → 切片」。

## 一条命令跑完整条管线

**处理整场（推荐，直接传主播目录）**：



```
cd DouyinLiveRecorder
# 自动识别该目录下的场次（按日期+时间间隔分组），默认处理最新一场
.venv/bin/python postprocess/auto_minutes.py "downloads/抖音直播/<主播>"
# 或指定日期：--date 2026-10-24
```

**处理单个录像**：



```
.venv/bin/python postprocess/auto_minutes.py "downloads/抖音直播/<主播>/<录像>.ts"
```

脚本依次完成：



1. **整场合并（墙钟对齐）**：录制默认 30 分钟一个 TS，重连 / 重启还会产生碎片。脚本逐段抽 16kHz 单声道音频（PCM 无时间戳，断流碎片互不影响）再重编码拼成整场 m4a（2 分钟约 0.5MB，8 小时约 115MB）。
   - 同一进程的连续分段文件名时间戳相同、后缀递增（`_000/_001…`），PTS 连续无缝；
   - 不同进程的重连碎片时间戳不同，**墙钟之间有录制中断缝隙**，脚本在缝隙处插入等长静音，让整场音频/逐字稿/弹幕/在线人数共用**同一墙钟时间轴**（这样 20:29 的弹幕命中才能在录像里精确定位）。

2. **自动分段**：超过 5.5 小时按妙记单文件上限（6h/6GB）自动切段。

3. **上传并生成妙记**：`lark-cli drive +upload` → `lark-cli minutes +upload`，自动转写。

4. **轮询取逐字稿**：带说话人分离、精确时间戳（到毫秒）、自动关键词，按全局时间偏移合并成整场。

5. **关键词命中**：输出 `<场>_segments.json`（话术信号）、`<场>_parts.json`（墙钟时间轴 + 源 TS 分段）、`<场>_逐字稿.txt`。

## 生成爆品报告（三类信号合并）

妙记跑完后，把「**妙记话术 + 弹幕关键词 + 在线人数突增**」按墙钟时间轴合并成一份可直接给客户的报告，并产出统一切片清单（相邻 45 秒内的多个信号归并为同一爆品时刻）：

```
.venv/bin/python postprocess/build_report.py "downloads/抖音直播/<主播>"
# 输出：<场>_爆品报告.md（概览/人数表现/爆品时刻时间线/高频转化话术/局限）
#       <场>_segments_final.json（合并后的统一切片清单，顺序即 clip_001、clip_002…）
```

然后用 `_segments_final.json` 切片，多 TS 自动定位到对应分段、**无需先合并整场视频**：

```
.venv/bin/python postprocess/clip_segments.py "downloads/抖音直播/<主播>/<场>_parts.json" \
    "downloads/抖音直播/<主播>/<场>_segments_final.json"
```

成片输出到录像旁的 `clips/` 目录，文件名带命中关键词与信号来源，**序号与报告时间线表格一一对应**。

> 完整流程（下播后）：① `auto_minutes.py <主播目录>`（合并+妙记+话术）→ ② `build_report.py <主播目录>`（报告+合并清单）→ ③ `clip_segments.py <parts> <segments_final>`（切片）。弹幕/人数信号由信号采集守护在**开播时实时落盘**（见 `../../signals/DouyinLiveWebFetcher/README_信号采集.md`），报告自动读取。

## 关键词清单（按客户业务口径调整）

默认内置：`上链接、1号链接、库存、到手价、最后、仅剩、321、首发、拍、券、秒杀、抢、卖完、补货、加购、下单、价格`。

自定义：



```
.venv/bin/python postprocess/auto_minutes.py 录像.ts --keywords "上链接,库存,到手价,最后50单,321"
```

> 这份清单需要客户业务方确认（什么话术算爆品信号）。一期先粗筛，误报靠人工删 JSON 行；跑几场后沉淀稳定清单。

## 单文件脚本（可单独使用）



| 脚本                      | 作用                                                  |
| ----------------------- | --------------------------------------------------- |
| `extract_audio.sh`      | 只抽音频（TS→16kHz m4a）                                  |
| `auto_minutes.py`       | 抽音频（墙钟对齐+缝隙静音）→ 飞书妙记全自动转写 → 关键词 segments.json |
| `build_report.py`      | 合并话术/弹幕/人数三类信号，产出 `_爆品报告.md` 和 `_segments_final.json` |
| `clip_segments.py`      | 按 segments 切片，默认重编码精确切；`--copy` 流拷贝秒切（切点对齐关键帧）；墙缝时刻自动 clamp 到下一段段头 |
| `segments.example.json` | 片段清单格式样例                                            |

## 前置条件



* 已安装并登录 `lark-cli`（飞书），账号有云空间上传与妙记权限。

* ffmpeg 在 `~/.local/bin/ffmpeg`（或 PATH 中）。

## 限制与注意



* 妙记单文件 **≤6 小时、≤6GB**，脚本自动按时长分段；多个分段的逐字稿按时间偏移合并到同一份 segments.json。

* 切片靠 `*_parts.json` 把全局墙钟时间映射回具体 TS 分段（已抽帧验证定位准确）。注意：多 TS 是独立录制进程产生、时间戳各自从 0 开始，**不能直接** `cat` **或** `concat -c copy` **合并视频**（会只取一段 / 花屏），脚本走的是音频 PCM 重拼（墙缝插静音）+ 段内定位切片。

* 时间轴统一以**墙钟**为准：弹幕/人数事件的真实时间与录像 `_parts.json` 的 `offset` 都相对首段墙起，重连缝隙由静音补齐，切片不会因为断流累积错位。

* 同目录按 "日期 + 相邻间隔 >2 小时视为另一场" 分组；同一天多场会分别列出，默认取最新一场。

* 转写是异步的，2 分钟样本约 1 分钟完成；8 小时整场预计 20–40 分钟，脚本会自动轮询。

## 已验证（2026-10-24）



* 2 分钟样本自动上传 → 妙记 → 转写：识别出双主播、精确时间戳、自动关键词（性价比 / 保质期 / 门店等）。

* 关键词命中 2 段（"拍 / 券 / 抢"、"首发"），切片成片 29s/53s，H264+AAC 540×960 正常播放。

* 整场多 TS：5 个碎片（1:54/0:26/4:16/1:24/10:08）正确识别为一场，音频合并为 18:08；跨段全局时间戳（05:00）准确定位到第 3 段并切片，抽帧与源视频对应画面一致。

* 墙钟对齐（XIAOQSTUDIO，开播前 3 次重连碎片 + 稳定后 `_000/_001` 连续段）：墙缝 86s/69s/30s 自动插静音，`_001` 连续段墙起正确推算为 20:19:27，无错位；20:29:57 弹幕「模特可以上链接吗」与 20:30:04 人数突增（842→985，+17%）相隔 7 秒，被报告归并为同一爆品时刻，按墙钟定位到 `_001` 段内切片，抽帧为当时模特走秀画面，时间对齐准确。
